Guide

How to read what Tracelucid shows you

A field-by-field reference for every view, panel, and control in the app — organized in the order you'll actually use it: open a capture, read the dashboard, then drill into whichever view answers your question.

On this page

1. Getting started

Everything in the header bar, before you've opened anything.

ControlWhat it doesWhen to use it
Open capture...Opens a native file picker for .pcap/.pcapng/.cap files. Select multiple at once — they're merged into one chronological capture using Wireshark's own mergecap, not re-implemented merging logic.Standard offline analysis: you already have a capture file (or several) to review.
Live capture...Lists your network interfaces; pick one and click Start. The dashboard updates automatically roughly every 1.5 seconds while it runs. While a file is loading, an import progress bar shows packets processed (and an estimated total, when known), with a Cancel button.

2. The dashboard

Everything below the capture's file name, visible as soon as a capture is loaded. Read top to bottom: Health tells you if there's a problem, Findings tells you what and why, Latency tells you about delay specifically, and the stat tiles give you the raw scale.

2.1 Network health

FieldWhat it meansWhen to use it
CategoryExcellent / Good / Needs Attention / Poor / Critical — color-coded.The first glance — tells you in one word whether this capture needs a closer look.
ScoreOut of 100, computed transparently from the factors below it — never a black-box number.Comparing two captures at a glance, or tracking whether a fix helped.
FactorsEach factor feeding the score: its own severity pill, a short name, and a plain-language description of exactly what was measured.Understanding why the score is what it is — every factor is a real, checkable measurement.

2.2 Findings

Each finding describes one specific thing the analysis engine detected — always with the evidence to back it up.

FieldWhat it meansWhen to use it
Severity pillcritical / warning / info, color-coded.Triaging quickly when there are many findings.
×N badgeFindings sharing the same category and title collapse into one card with a ×N count. Click the header to expand each occurrence.Captures with a repeated pattern — avoids a long scroll of near-identical cards.
DescriptionA plain-language sentence naming the specific hosts/values involved.The fastest way to understand what happened, in words.
Technical explanationA more detailed, technically precise version of the same finding.When you need the precise mechanism, not just the summary.
Possible causesPlausible explanations — deliberately including benign ones alongside concerning ones.Before assuming the worst — most findings have an innocent explanation too.
View evidenceJumps to the exact packets behind this finding, scrolling the packet table into view automatically. For a ×N card, covers every occurrence at once.Verifying a finding against the raw data — nothing is asserted without a pointer to real packets.
Explain with AIOptional — only if you've added an Anthropic key in Settings. Simple / Detailed / Expert.When you want a different level of detail than the fixed text provides.

3. The detail views

The toggle buttons below the dashboard — Show timeline / Show flows / Show hosts / Show conversations / Show packet table (expert view). Independent: open any combination. Clicking a row in any of these jumps to that row's packets, scrolling the packet table into view automatically.

3.1 Timeline

A chronological log of notable events — connections opening/closing, and findings — in the order they actually happened.

FieldWhat it meansWhen to use it
TimeWhen the event happened; format follows Appearance → Time format.Establishing exact timing.
EventA severity-colored category badge (tcp, dns, security...) plus the event's title.Scanning for what kind of thing happened, and when.
EvidenceHow many packets back this event.Jumping to the exact packets behind a specific moment.
When to use this viewYou care about sequence and timing — "did the retransmission happen before or after the reset?" The only view that interleaves everything in strict chronological order.

3.2 Flows

Every distinct network conversation — a "flow" is one unique combination of two endpoints (address+port) and a transport protocol.

FieldWhat it meansWhen to use it
TransportTCP, UDP, ICMP, etc. — color-coded.Filtering mentally by protocol type.
Endpoint A / BThe two sides, as address:port. A magnifying-glass icon appears if threat-intel is enabled.Identifying exactly who talked to whom, on which port.
PacketsPackets in this one conversation.Spotting unusually chatty conversations.
BytesTotal data transferred in this single conversation, both directions.Finding the single biggest transfer — sort this column.
HandshakeTCP only: time to establish (SYN → SYN/ACK).Diagnosing whether a specific connection was slow to start.
Contents"Visible" or "Encrypted" (TLS) — a factual state, not a problem by itself.Knowing upfront whether deeper inspection is even possible.
First/Last seenTimestamps bounding this conversation.How long this specific conversation lasted.
StatusTCP: state + retransmission/dup-ACK counts. DNS: query/failure counts.The fastest per-row health check — red pills flag problems immediately.
When to use this viewThe most direct answer to "who talked to whom, and how did it go?" Sort by Bytes to find your single largest conversation. Click any row to Follow the stream and read the reassembled conversation.

3.3 Hosts

Traffic aggregated per individual IP address — every flow that address was part of, summed together.

FieldWhat it meansWhen to use it
HostThe IP address; magnifying-glass icon if threat-intel is enabled.Identifying every machine that appeared in the capture.
ScopeInternal or External (private/RFC1918 vs. real routable).Separating your own machines from anything outside your network.
Packets / BytesTotals across every flow this host was part of.Finding your biggest talker overall — sort by Bytes.
FlowsDistinct conversations this host was part of.Spotting an unusually social host.
PeersDistinct other addresses this host talked to.A high peer count, especially to many external addresses, is worth a look.
TransportsProtocols this host used.Understanding what kind of traffic a host generated.
First/Last seenBounding timestamps across all activity.How long this host was active.

The search box filters by address, scope, or transport. Multiple terms: space/comma = OR; write AND to require both. Whole-term aware, so 203.0.0.1 won't also match 203.0.0.10.

When to use this view"Who is the biggest talker in this capture?" Sort by Bytes. Also the fastest way to separate internal from external machines.

3.4 Conversations

Traffic aggregated per pair of hosts, regardless of port/protocol — broader than Flows, which splits the same pair into separate rows.

FieldWhat it meansWhen to use it
Host A / BThe two addresses in this pair.Identifying a specific pair of machines.
Packets/Bytes/FlowsTotals across every flow between exactly this pair.Total data between two specific machines, across everything they did.
TransportsEvery protocol used between this pair.Seeing the full relationship between two hosts in one row.
First/Last seenBounding timestamps across everything between this pair.How long this pair's relationship spanned the capture.

Same search syntax as Hosts.

When to use this view"How much total data moved between these two machines, across everything they did?" More direct than Flows, which would split the same pair across several rows.

3.5 Packet table (expert view)

The raw, individual-packet view — closest to what a tool like Wireshark shows. Every other view is a summary built from this data.

FieldWhat it meansWhen to use it
#Packet number.A stable reference for a specific packet.
TimeThis packet's timestamp; format follows the Appearance setting.Exact timing of one specific packet.
Δ TimeTime since the previous row currently shown — most useful filtered to one flow, revealing gaps/bursts within it.Spotting an unusual pause or burst within one flow's sequence.
Source / DestinationThe two addresses for this packet.Direction of this specific packet.
ProtocolColor-coded badge.Visually scanning a mixed-protocol capture.

The filter box supports the same multi-term syntax. A "Showing X of Y loaded" counter with "Load more" replaces silent truncation. Click any row for its full raw decoded fields in the pane on the right — including a Context section cross-referencing the flow and any finding this exact packet is evidence for.

When to use this viewThe ground truth. Verify a finding, or get exact byte-level detail no summary view provides.

4. Other features

4.1 Export report

The "Export report..." button sits next to the capture's file name, above the dashboard. Opens a checklist — Network health, Findings, Flows, Hosts, Conversations, Timeline — pick any combination, then "Export to PDF..." opens a native save dialog.

4.2 Follow stream

Click any row in Flows to reassemble that conversation's payload into a readable, direction-colored exchange — the same mechanism behind Wireshark's "Follow TCP Stream." HTTP-aware mode dechunks Transfer-Encoding: chunked bodies automatically; a Text/Hex toggle handles binary or encrypted content; and clicking any reassembled chunk jumps straight to the exact packet that carried it.

4.3 IP reputation lookup

The magnifying-glass icon next to an address (Flows and Hosts) checks that one IP against a provider you choose in Settings (AbuseIPDB or VirusTotal). Opt-in and manual only — only the address you click is ever sent. Shows a risk score out of 100, a summary, organization/country, and provider used.

4.4 Appearance

FieldWhat it meansWhen to use it
ThemeSystem (follows OS), Light, or Dark.Personal preference or matching a presentation environment.
Accent colorSix presets: Blue, Teal, Purple, Orange, Pink, Green.Personal preference.
Time formatSeconds (raw epoch, Wireshark default), Local time, or Relative (elapsed since first packet).Local time to correlate with a real-world clock/log file; Relative when only elapsed time matters.

4.5 Settings: AI explanations & threat intelligence

Both off by default, both require your own API key — nothing is sent anywhere automatically.

  • AI Explanations (Anthropic/Claude): powers "Explain with AI" on findings. Only the specific finding you click is sent — never raw packets.
  • Threat Intelligence (AbuseIPDB or VirusTotal): powers the reputation lookups. Only checks the exact address you click.

6. Understanding data volume (bytes)

Byte counts appear at four different levels of granularity. Each answers a different question — picking the right one matters:

  • Bytes stat tile (2.4) — the whole capture, every host and conversation combined. Answers: "how big was this capture overall?"
  • Hosts → Bytes (3.3) — everything one specific address sent or received, across every conversation. Answers: "which single machine moved the most data?"
  • Conversations → Bytes (3.4) — everything transferred between one specific pair, across every port/protocol together. Answers: "how much data moved between these two machines?"
  • Flows → Bytes (3.2) — one single conversation (one pair, one port, one protocol). Answers: "which single conversation was the biggest?" — the finest-grained of the four.

A worked example: if a host downloaded a large file over one HTTPS connection, that transfer's size shows up identically in all four places — as part of the capture's total Bytes, as (most of) that host's total in Hosts, as that pair's total in Conversations, and as that one flow's own Bytes in Flows. If instead the same two machines had five separate connections that each moved some data, Conversations shows their combined total in one row, while Flows shows each of the five separately — useful for telling "one big transfer" apart from "many smaller ones that add up."

Also worth knowingA "Large outbound transfer to an external host" finding (2.2) fires automatically when one flow's outbound volume crosses a threshold — so an unusually large transfer often shows up as a Finding before you'd even need to go sorting tables by Bytes yourself.
